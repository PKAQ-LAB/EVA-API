## 1. 目的与授权边界

总控转达 S0 现场：角色新增 DATA_SCOPE 下拉为空，包 S 尚无创建对象或授权。包 S 批准不隐含共用内置字典数据修复批准。本提案只恢复原 DATA_SCOPE 主项及已实现的五个原明细，另列缓存单键失效和回退；不提供可执行 SQL，不实现或操作数据。

不恢复系统/MENU 根、其他字典、八种全部选项、旧叶子，不调整 PID/PATH/两根归属、字典列表 children 契约或 D01 remark；不创建新字典 ID、账号、角色、授权、租户/schema，不改任何已有角色的 dataScope，不改前后端生产代码、配置或服务。既有 SYS_DICT_ITEM 是当前物理映射；已读取新的 _line/_ref 命名权威规则，本次不借修复重命名存量表或迁移。

## 2. 已核源码链路

角色 `aoeform.tsx` 使用 `DictSelector code="DATA_SCOPE" showall={false}`，表单必选；组件按 GET `/api/sys/dictionary/query/DATA_SCOPE` 读取 response.data 的键值映射，不在该页面合成“全部”选项。无需增加前端默认 0000，也不能用硬编码八选项绕过后台数据。

后端 GET `/sys/dictionary/query/{code}` → `DictService.queryDict`：空 code 返回空；先读 DictCacheHelper，非 null 的空 map 也直接命中返回；未命中才 selectDictByType 后写缓存。主项条件为 code 精确等于 DATA_SCOPE、FROZEN != 1，加 MyBatis-Plus 逻辑删除过滤及既有数据权限处理；明细按 MAIN_ID 查、逻辑删除过滤、SORT/ID 顺序，再排除 FROZEN=1，映射 D_CODE→D_VALUE。PID/父根不是此单项查询条件，修复选择器无需先恢复系统根。

源码 DataPermissionEnumm 虽声明八值，实际 handler 只实现 0000 ALL、0001 本部门、0002 本部门及子部门、0003 指定部门、0007 创建/修改者；其他条件不合成放行。RoleService.validateDataScope 新授 null/blank/非法值及 0004/5/6 均拒绝；编辑遗漏范围保留真实原值与组织关联，0003 必须有合法组织。恢复下拉不能改变这些守卫；明确选择 0000 才是 ALL，恢复选项本身不授予 ALL。

## 4. 系统只读与来源归属

当前只读语义是 FrozenEnumm.READ_ONLY=9999，FROZEN=1 是锁定不查询；两者不得混淆。DictService 的主项 edit/del 拒绝 READ_ONLY，switch 跳过 READ_ONLY；并非已经实现两根系统分类守卫。六条原行实为0，本包不改变冻结态，不能把恢复可用选项称为恢复系统只读；系统全局只读政策独立于本次下拉修复。不得临时改冻结态再走普通 edit，后者会差异保存明细并可能删除未提交行。

本包仅当前已获准 standalone 开发实例的真实 schema/source。`queryDict` 有 @TenantSchema，路由器非 schema 模式不绑定新 TenantContext；schema 模式则按可信 tenant 路由并用 schema::code 缓存键，当前代码不是已落地的全局 core 系统字典聚合。禁止把“系统内置”解释为跨租户恢复、复制或 core 回退；正租户、core、tenant 副本全部排除。本轮运行实际 owner/context 由 backend/总控已有只读证据确定，来源不明则停止。

数据权限处理仍可能约束字典 Mapper 读取；不得用个人受限查询生成共享字典缓存。此次验收先由既有获准管理员在合法页面读回准确五项；受限身份查询若仍失败或产生空缓存，记录为独立来源/共享读契约问题，不给其 ALL、不全局 Ignore、不借此修复扩大 Mapper 权限。

## 5. 缓存失效与页面重读

CacheManager 的缓存名为 dictdata；DictCacheHelper.scopedKey 在无 schema 上下文时为 DATA_SCOPE，有上下文时为 `<可信schema>::DATA_SCOPE`。Redis 物理 key 还叠加 CacheManager 前缀/序列化，不能把两种逻辑键同时删来试错。源码 dictdata TTL 配置为 0s，不承诺等候自动过期；“不缓存 null”不等于空 map 不缓存。

数据事务提交并复核成功后，仅失效本次真实来源对应 DATA_SCOPE 的一个缓存条目，不全局 flush、removeAll、init、重启或批量删字典。优先由执行者使用已核运行 CacheManager 的 dictdata cache 单键 evict；当前 DictCtrl 没有单键驱逐端点，不能凭空调用 URL。若采用受控 Redis 单键删除，须先只读确认同一应用 Redis/db/物理键及原值指纹，删除前比较快照防并发，授权包明确该单键与工具路径；原值只含字典映射，仍仅保存在受控维护备份，不输出认证材料。无法确定键与安全执行方式时停止于未完成，不改TTL、不加临时生产接口。

之后由合法管理员 GET 单项查询使服务按当前数据重建五项 map，再关闭重开角色新增抽屉使 DictSelector 的 effect 重新加载；不把刷新按钮或浏览器重载当后端缓存失效证据。返回值须恰好五个 code，顺序按原 SORT/ID，0004/5/6 不出现；新增表单保持未选，不自动填 0000。数据提交和缓存不是一个原子事务，单键驱逐/回填失败须报告并暂停 S，不标记已恢复。
